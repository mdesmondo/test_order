# Расчёт рекомендуемого заказа поставщикам (`order_calculator`)

Консольная утилита на чистом **Python 3.10+** (без сторонних зависимостей) для автоматизации ежедневного расчёта закупок товаров на склад. Программа анализирует текущие остатки, товары в пути, среднедневные продажи, сроки поставки и страховой запас, формируя наглядный отчёт для менеджера по закупкам.

## Структура проекта

* `order_calculator.py` — основной модуль с моделью данных, валидацией, бизнес-логикой, загрузчиком CSV и CLI-интерфейсом.
* `products.csv` — демонстрационный набор из 9 товаров, покрывающий как базовые примеры из задания (`A001`–`A006`), так и дополнительные граничные сценарии (`A007`–`A009`).
* `test_calculator.py` — набор автоматических модульных тестов (`unittest` / `pytest`) из 17 проверок.
* `README.md` — документация проекта, примеры запуска и архитектурное обоснование.

## Требования и запуск

Программа использует только стандартную библиотеку Python (`dataclasses`, `csv`, `math`, `pathlib`, `argparse`, `unittest`) и не требует установки сторонних пакетов через `pip`. Минимальная версия — **Python 3.10**.

**1. Запуск расчёта по умолчанию (ищет `products.csv` рядом со скриптом, иначе использует встроенный набор):**
```bash
python3 order_calculator.py
```

**2. Запуск с указанием собственного CSV-файла:**
```bash
python3 order_calculator.py --file path/to/custom_products.csv
```

## Запуск тестов

Через встроенный модуль `unittest`:
```bash
python3 -m unittest test_calculator.py -v
```

Или через `pytest` (если установлен в окружении):
```bash
pytest -v
```

## Обоснование архитектуры и формул (для устного собеседования)

### 1. Разделение ответственности (Separation of Concerns)

1. **Модель данных и валидация (`Product`, `OrderCalculation`)** — иммутабельные датаклассы (`frozen=True, slots=True`). Вся проверка корректности данных выполняется в `__post_init__` при создании объекта, поэтому в расчётную функцию физически не может попасть невалидный товар.
2. **Чистая бизнес-логика (`calculate_order_for_product`)** — детерминированная чистая функция без побочных эффектов, ввода-вывода и глобального состояния. Принимает `Product`, возвращает `OrderCalculation` со всеми промежуточными метриками. Благодаря этому её легко тестировать и переиспользовать (например, подключить к веб-API или Telegram-боту).
3. **Слой работы с данными (`load_products_from_csv`, `load_products`)** — отвечает за чтение CSV в кодировке `utf-8-sig` (корректно обрабатывает BOM, если файл сохранён из Excel), проверку наличия всех колонок, уникальности `sku` и информативные сообщения об ошибках с указанием номера строки.
4. **Слой представления (`format_report`)** — принимает уже готовые объекты `OrderCalculation` и строит текстовый отчёт, не вмешиваясь в математику.

### 2. Логика формул и тонкости округления
* **Период покрытия (`coverage_period = lead_days + 7`)**: нам нужно пережить время доставки новой партии (`lead_days`) плюс обеспечить 7 дней торговли после её прихода до следующей закупки.
* **Почему `math.ceil`, а не `round`**: поставщики отгружают товар в целых штуках. Обычное математическое округление (`round(13.25) -> 13`) приведет к дефициту (out-of-stock) в последний день покрытия или «съест» страховой запас. Округление вверх гарантирует стопроцентное покрытие спроса.
* **Защита от погрешности IEEE 754 (`round(..., 9)` перед `math.ceil`)**: в двоичной арифметике с плавающей точкой `1.15 * 20` даёт `23.000000000000004`. Прямой вызов `math.ceil` вернул бы `24` вместо `23` (лишняя единица товара). Предварительное сглаживание `round(val, 9)` отсекает микроскопический хвост float, сохраняя правильное округление вверх для реальных дробных значений.
